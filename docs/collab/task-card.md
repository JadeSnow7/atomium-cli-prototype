# 任务卡模板

> 普通任务（R0/R1）开工前先在交接消息或 Draft PR 中完成任务卡与可行性确认，提交时贴进 PR 描述；R2 任务或跨多个 PR 的任务另存为 `docs/collab/tasks/<编号>-<短标题>.md`。
> 前 5 个字段是必填核心字段，"附加信息"部分按需填写。禁止在任何字段中出现明文凭据。

```markdown
## 任务 <编号>：<一句话标题>

**风险档位**：R0 / R1 / R2　　**授权等级**：A0 / A1 / A2（A2 需注明 Owner 批准记录；若依赖 Owner 执行 A3 步骤，另注"含 A3 前置项"）
**执行负责人**：　　**评审者**：　　**集成人**：Claude

### 1. 目标
<要解决什么问题；用户可观察到的结果是什么>

### 2. 验收条件
- [ ] <可观察结果 1>
- [ ] <可观察结果 2>
- [ ] 拒绝场景：<该被拒绝的行为确实被拒绝>（隔离 / 权限类任务必填）
- [ ] 验证环境：<OS 版本、架构、关键依赖>

### 3. 基线
- 起始提交：`<sha>`
- 依据的规格 / ADR：<链接与版本>

### 4. 验证证据
- 交付提交：`<sha>`
- 执行的命令与结果：<例如 `pnpm run ci:local` → 通过>
- 原始日志 / 输出位置：<路径或链接>

### 5. 未验证部分与剩余限制
<失败、跳过、未覆盖的环境或场景；没有就写"无"。例：macOS 原生行为未验证>
```

```markdown
- 问题与证据：
- 影响：
- 可选方案：
- 推荐方案：
- 审批：Claude（A1）/ Owner（A2）

### 评审记录

- [ ] 已发布（需 Owner 授权）
```
